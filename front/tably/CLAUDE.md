# tably-front — Claude Code 작업 규칙

## 프로젝트 컨텍스트

- tably(예약금 기반 노쇼 방지 예약 시스템)의 프론트엔드
- 목적: **백엔드 시연용.** 이 프로젝트의 심사 대상은 백엔드이며, 프론트는 기능을 보여주는 액자다
- 착수 시점: 백엔드 P1 완성 후 (요구사항 `../docs/requirements.md` 9번 일정 참조). 그 전에는 이 폴더에서 작업하지 않는다

## 범위 (엄격)

화면은 딱 2개만 만든다:
1. **예약 화면** — 식당의 날짜별 슬롯 조회 → 슬롯 선점 → 예약금 결제 → 확정 표시
2. **웨이팅 화면** — 웨이팅 등록 → 내 순번 폴링 표시("내 앞에 N팀") → 호출 알림 표시

만들지 않는 것: 로그인 화면 고도화(토큰 하드코딩 또는 최소 폼), 식당 목록/검색, 관리자 화면(Swagger로 대체), 라우팅 구조 확장, 반응형 대응

## 기술 규칙

- 스택: Vite + React. **상태관리·UI 라이브러리 추가 금지** (필요하다고 판단되면 먼저 제안만 하고 승인 대기)
- API는 back의 Swagger 명세 기준. **임의로 필드나 응답 구조를 추측하지 말 것** — 불명확하면 질문
- 디자인은 최소한으로. 기능이 눈에 보이는 것이 목적
- 컴포넌트는 화면당 3~5개 이내로 단순하게

## 대화 규칙

- 존댓말 사용
- 작업 후 변경 파일 목록과 실행 방법(npm 명령 포함)을 요약할 것
- 백엔드 코드는 절대 수정하지 않는다. API가 이상하면 수정하지 말고 보고할 것
