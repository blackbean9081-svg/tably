# tably

> 예약금 기반 노쇼 방지 레스토랑 예약 시스템
> "매월 1일 10시, 5,000명이 240개 슬롯에 몰려도 중복 예약 없이 버티는 서버"

## 해결하는 문제

**1. 예약 오픈런 동시성** — 인기 식당 예약 오픈 순간, 같은 슬롯에 수백 명이 동시 요청해도 정확히 1명만 성공해야 한다. DB 락(비관적/낙관적) 비교 구현 → 부하 테스트로 한계 측정 → Redis 분산락 전환까지, 각 단계의 성능을 수치로 기록한다.

**2. 결제 정합성** — 예약금 결제의 중복 요청 방지(멱등성), PG 응답 유실 시 UNKNOWN 상태 처리, 환불 실패 기록과 재처리. "돈은 나갔는데 예약은 없는" 상황을 시스템이 스스로 복구한다.

**3. 번복 가능한 상태 설계** — 노쇼는 "몰수 끝"이 아니다. 사장의 방문 처리 누락, 이의신청 인용 등 실제 운영에서 벌어지는 번복을 상태 머신과 정산 조정으로 다룬다.

## 기술 스택

Java 21 · Spring Boot 4.1 · Spring Security(JWT) · JPA/QueryDSL · PostgreSQL 18 · Redis(2막 도입) · k6 · GitHub Actions

## 프로젝트 구조

```
tably/
├── docs/     # 요구사항, ERD, API 명세, 부하 테스트 리포트
├── back/     # Spring Boot API 서버
└── front/    # React (백엔드 완성 후 착수 — 예약/웨이팅 2화면)
```
